# Roblox標準画像の対応表

`builtin-asset-catalog.json` は組み込み画像パスから配信アセットIDへの対応表。画像本体は含めない。

| 対象パス                                                     | 件数 |
| ------------------------------------------------------------ | ---: |
| `textures/`（旧ツール画像、カーソル、UI、SpawnLocationなど） |  175 |
| `icons/`                                                     |   59 |
| `sky/`                                                       |   10 |
| 合計                                                         |  244 |

`sky/` は画像としての解決に対応するという意味で、ワールドのSkyオブジェクトを描画する機能は含まない。

## 出典と確認方法

- 一次資料: Roblox Studio for macOS `0.739.0.7390687` の配布実行ファイル `Contents/MacOS/RobloxStudio`。
- 実行ファイルSHA-256: `3bc965f6a4220d2b8fe2fa1de8f055cd29fc026caf764d9552c08a9cf8aae645`。
- 実行ファイル中の `rbxasset://...png` / `.jpg`、NUL、数値ID、NULの連続文字列から243件を抽出。重複パスのID競合がないことを確認した。
- SpawnLocationのパスとIDは同実行ファイル中に別々に格納されているため、[配信IDの調査報告](https://devforum.roblox.com/t/roblox-spawn-point-original-image-missing/3166362/2)と配信画像で別途確認した1件を加えた。
- 2026-09-21に244件すべてを公式配信APIから認証なしで取得し、画像全体のデコードを検証。PNG 232件、JPEG 12件。画像はメモリ上だけで処理し、リポジトリへ保存していない。

これは上記Studioの配布物から作成した対応表で、Robloxが公開している全標準素材の公式一覧ではない。ファイル名からIDを推測したものや、第三者が再アップロードした代替画像は含めない。

## 解決方法

1. `rbxasset://` のパスを読み、大文字・小文字と `\` / `/` の違いを正規化する。
2. 表にある画像は `assets/{id}` に揃え、`rbxassetid://{id}` と同じ取得キューに入れる。同じIDは一度だけ取得する。
3. 数値IDでの事前配置があれば利用し、なければ設定済みの取得API、または開発用プロキシ経由で取得する。表にある画像を `builtin/` 配下に置く必要はない。
4. 表にないパスは従来どおり `builtin/` 配下の配置先を探す。配信IDを推測せず、不足は警告する。

この対応表で標準画像すべてを網羅したわけではない。例えば手元のStudioにファイルとして存在する `textures/face.png`、`textures/grid4.png` は、今回の資料から配信IDを確認できていないため未登録。

本番ブラウザからの直接取得はRoblox側のCORSで止まる。画像を自前配信しない本番運用には、`PUBLIC_ROBLOX_ASSET_API_URL` で取得用サーバーを指定する必要がある。詳細は `README.md` を参照。

## 配信状況の再確認

```sh
pnpm --dir frontend run roblox:verify-builtins
```

APIキーは不要。最大4件並列で全IDのHTTP応答とPNG/JPEGのデコードを検証する。画像も対応表も書き換えず、失敗したパス・IDを表示して終了コード1を返す。通信失敗の場合はネットワークの状態を確認する。対応表を更新するときは出典とStudioバージョンも更新する。
