# 点群から3Dメッシュを生成

点群登録画面で「3Dメッシュ」を選ぶ。座標系指定、自動配置、地図上での位置合わせに対応する。生成結果は頂点色を持つGLBの `MeshEntry` として、既存のプレビュー・レイヤー管理に渡す。

## 地形（最高点）

XY平面の最長辺を「細かさ」の4倍で分割し、最寄りの格子点ごとに最高標高の点を選ぶ。XYを格子点にそろえ、高さとRGBは選ばれた点から引き継ぐ。四隅に点がある格子だけを2枚の三角形でつなぎ、欠測点の周囲は補間しない。対角線は両端の標高差が小さい方を選ぶ。法線は生成した三角形から計算する。「つながりの強さ」は使わない。

建物や樹木を含めた上面（DSM相当）を作る処理であり、地面の点だけを抽出する処理ではない。絶壁も格子間の斜面になり、張り出しや裏面は表現しない。最高点に含まれる外れ値も残る。細かさ192で最大769×769頂点、約118万面となる。

## 立体物の処理

1. XYZを原点からのメートル座標へ変換する。高さは保持する。
2. 3Dグリッドごとに代表点を選ぶ。点の重複で面が膨らまないようにする。
3. 「建物・広域」（初期選択）と「表面を復元」では、k-d treeで近傍16点を探し、共分散行列の最小固有ベクトルから法線を推定する。近傍グラフのPrim探索で似た法線から順に向きをそろえる。
4. 局所接平面への符号付き距離をコンパクトな重みで平均し、Marching Cubesでゼロ面を取り出す。近傍点の支えがないセルの面は除外し、未観測領域との境界に膜を作らない。
5. 近傍点のRGBを線形色空間へ変換し、頂点色としてGLBに格納する。
6. 地理座標の原点とGLBから `MeshEntry` を作る。開いた壁を両側から表示できるよう、GLBは両面描画にする。

「建物・広域」では、近傍が角をまたぐときに支持点の多い平面を選び、向きの違う壁と屋根の距離を混ぜにくくする。全体で代表点と法線を共通にした後、同じ格子の48セル単位で面を作る。隣の区画と境界の計算順序をそろえ、位置・法線・色を一致させる。区画内の頂点はインデックスで共有し、すべての区画を一つのGLBに格納する。3D Tilesへの分割は行わない。

計算とGLB生成はWeb Worker内で行う。外部変換サービスやWASMの追加取得は不要。入力配列は転送で切り離さず、失敗後も再試行できる。登録画面のキャンセルや破棄時にはWorkerを停止する。

## 設定と限界

- 細かさ: 32〜192、初期値128。「建物・広域」は最長軸を指定値の4倍で分割する。「地形（最高点）」はXYの最長軸を指定値の4倍で分割する。「表面を復元」は指定値から余白を引いたグリッド数を使う。
- 「建物・広域」の上限: 代表点120万点、500万面。超過時は細かさを下げるよう案内する。区画の作業グリッドは約4.9 MiBで固定だが、入力・近傍グラフ・出力GLBのメモリは点数と面数に応じて増える。
- つながりの強さ: 1〜3、初期値2。「建物・広域」では指定値の1.5倍と点間隔の2倍の大きい方を支持半径とし、上限6セル。「表面を復元」では重みの支持半径をセル単位で調整する。点間隔の2倍も考慮し、上限は10セル。
- 「表面を復元」の上限: 代表セル20万。三角形は最低25万、細かさ128で45万、192で101.25万まで、細かさの二乗に応じて増やす。超過時は結果を切り捨てずエラーにする。
- 細かさを上げるとセルと面が小さくなる。同じ「つながりの強さ」でもメートル換算の近傍半径が小さくなるため、疎な点群では面が途切れる場合がある。その場合はつながりを強めるか、細かさを下げる。
- 「表面を復元」ではグリッドのメモリ使用量は細かさの三乗に比例する。192では約347 MiBをグリッドと面に確保する（入力、近傍グラフ、出力コピー、GLB生成を除く）。通常設定では面のバッファを小さく確保する。
- 「建物・広域」と「表面を復元」は局所接平面による近似であり、Poissonの大域的な最適化ではない。ノイズが多い点群、密接する薄い面、樹冠内部の点では法線が不安定になり、穴や誤接続が残り得る。未計測の裏面は復元しない。
- Google Photorealistic 3D Tilesのような写真テクスチャの復元は行わない。色の情報量は入力RGBと生成メッシュの解像度に依存する。写真テクスチャには撮影画像とカメラ情報を使う別経路が必要。
- 穴より大きな近傍半径を選ぶと穴が埋まる。細枝・葉・隣接面も同様につながる。離れた外れ値はグリッド全体の解像度を下げるため、対象範囲を絞った点群を使う。
- RGBなしの場合は単色。LASのRGBAはRGBへ正規化する。
- 現在の入力が経緯度のFloat32配列なら、その段階で失われた座標精度は復元できない。自動配置経路のメートル差分座標は維持する。

## 検証

`pnpm --dir frontend exec vitest run src/routes/map/utils/formats/pointcloud`

区画サイズを変えても三角形・法線・色が完全一致することと、途中経過の通知後もキャンセルできることを確認する。架空の垂直面・斜面で厚みのない復元と色の分離、球面で形状誤差と外向き法線、直線状の点群で復元不可を確認する。地形の最高標高と色の選択、欠測部分、座標配置、RGBA変換、キャンセルと再試行も検証する。

接平面から符号付き距離を推定する考え方は[Hoppeらの表面再構成](https://hhoppe.com/proj/recon/)を参考にしている。この実装は原論文の再実装ではなく、ブラウザの固定グリッドと局所的な距離平均を使う。
