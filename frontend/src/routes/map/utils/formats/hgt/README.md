# SRTM HGT

`.hgt`をブラウザ内のWorkerで解析し、既存の単バンドラスターまたは3Dメッシュentryへ渡す。追加の依存パッケージは使わない。

## 対応範囲

- 1度タイル: 1201×1201（SRTM-3）、3601×3601（SRTM-1）、1801×3601（高緯度用SRTM-1）
- 符号付き16ビットBig Endian、北→南・西→東の標高値（メートル）
- `-32768`をNaNへ変換し、値の範囲から除外する。負の標高と0は保持する
- `N00E000.hgt`のような南西端を表す名前、大文字・小文字、`.test-grid`のようなドット区切りの接尾辞
- 単体、複数ファイルからの選択、共通のZIP展開経由。複数選択は対象を1つ選んで登録する（モザイク化はしない）

0.5度タイル、7201×7201などの独自解像度、浮動小数点HGT、gzipの直接読み込みは対象外。ヘッダーがないため、規定サイズと名前の検査だけでは内容の真正性を判定できない。

## 座標と表示

座標系はWGS84。ファイル名の範囲はピクセル外縁ではなく端の標本点を表す。
ラスターのbboxは各方向に半セル拡張し、セル中心が標本位置に一致するようにする。3Dメッシュは端の標本点の範囲を既存のメッシュ生成へ渡す。
解析後にダイアログでGeoTIFFと共通の切り替えUIから「ラスター／3Dメッシュ」を選び、「決定」を押す。名前から位置を復元できれば、選んだ方法でそのまま登録へ進む。複数ファイルの場合は先に対象を1つ選ぶ。
名前から位置を復元できなければtransformをnullとし、選んだ表示方法を引き継いで位置合わせへ進む。座標系の推測はしない。
Web Mercatorの表示可能緯度を超えるタイルは自動配置を拒否する。

Terrariumエンコード・GeoTiffCache・標高メッシュは既存処理を共有する。解析Workerはキャンセルや入力変更時に終了し、古い結果を登録しない。

## 制限と検証

`definition.ts`の単体上限は25,934,402バイト（3601×3601×2）。読み込み前と配列確保前に規定サイズを検査する。複数入力やZIP展開後の合計容量警告は共通処理を使う。
`__fixtures__/test-hgt.ts`で人工格子を生成し、バイト順、標高・欠損、サイズ、位置、登録、Workerの解放、アップロード導線を検証する。

参照: [GDAL SRTMHGT](https://gdal.org/en/stable/drivers/raster/srtmhgt.html)、[GDALのSRTMHGT実装](https://github.com/OSGeo/gdal/blob/master/frmts/srtmhgt/srtmhgtdataset.cpp)。
