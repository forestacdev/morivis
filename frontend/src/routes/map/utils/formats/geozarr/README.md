# Zarr / GeoZarr

公開されたZarr v2 / v3のURLを、`RasterGeoZarrEntry` として登録する。
共通URL欄では `.zarr`、`.zmetadata`、`.zgroup`、`.zarray`、`zarr.json` を専用フォームへ渡す。
ディレクトリ名に拡張子がない配信元は「Zarr / GeoZarr」フォームから指定する。

配列そのもののURL、統合メタデータ付きグループの候補選択、配列パスの手入力に対応する。
HTTPにはグループ内のファイルを列挙する標準APIがないため、統合メタデータがないグループでは配列パスを入力する。
ローカルのZarrフォルダーとZIPは、共通アップロード欄または地図へドロップして登録する。フォルダー選択にも対応する。
内部の相対パスを保持し、配列選択から先はURL登録と同じフォームを使う。ローカルではファイル一覧から配列を列挙できるため、統合メタデータは不要。
複数のZarrルートを同時に含む入力は拒否する。1つずつ登録する。

フォルダーはFile参照をWorkerへ渡し、必要なファイル（Range読み取りではその範囲）だけ読む。ZIPは圧縮データ全体を読み込むが、各項目は必要になった時点で展開する。
ZIP入力は256 MiB、内部ファイル数は100,000個、メタデータは1ファイル8 MiB、チャンクファイルの読み取り・ZIP展開は1ファイル64 MiBまで。ZIP内の大きなshardは、部分参照でも展開上限の対象になる。
ローカルデータをサーバーへ送信しない。File参照はruntimeが保持し、entryには一時的な`zarr-local:`識別子だけを載せる。Worker再起動時は再接続できるが、ページ再読み込み・共有先ではフォルダーまたはZIPの再登録が必要。

## 描画

`protocol/geozarr/index.ts` はWorkerへの窓口。メタ情報取得、チャンク展開、数値の色付けは `geozarr.worker.ts` 内で行い、MapLibreの `addProtocol` へPNGタイルを返す。
表示設定はentryからsource URLへ反映し、画面からMapLibreのレイヤーを直接変更しない。
URL・配列パス・手動指定範囲を保持し、Workerを作り直した際もsourceの定義から接続を復元する。

- 数値型の2次元規則格子。時間・高度などの追加次元は先頭インデックスを使用する。
- 名前付きのband / channel軸、単一バンド、RGB合成、カテゴリ凡例。
- 1次元の経緯度・x/y座標軸からセル中心と外周を求め、昇順・降順を反映する。
- 軸順序 `[x, y]` / `[y, x]`、0〜360度の経度を扱う。
- EPSG:4326、3857、WGS84 UTMを扱う。各タイルの画素を元の座標系へ逆変換する。
- `_FillValue` / `missing_value` / `nodata` を透明にし、`scale_factor` / `add_offset` を適用する。Zarrの保存上のfill_valueだけでは有効な0を欠損とみなさない。

不等間隔格子、2次元の曲線座標、汎用の3D表示、時間・高度の選択UI、汎用の解像度ピラミッドの自動切り替えは対象外。地域索引付きGPMの高度選択は後述。
位置が分からない場合は経緯度の外周を手入力する。投影情報を持たないx/yだけでは元の座標系を特定できないため、事前に座標情報を付与する。

## 取得と上限

ファイル全体は取得せず、地図タイルに対応する配列の範囲を読む。低ズームではその範囲が大きくなるため、1回の読み取りは最大4,194,304画素、交差するチャンクの展開量は保守的な8バイト/要素換算で64 MiBまでとする。
上限を超える場合は拡大するか、配信側にある縮小解像度の配列を選ぶ。

展開済みチャンクは64 MiB、切り出し結果と描画済みタイルもそれぞれ64 MiBまでLRUで保持する。同じチャンクの取得は共有し、同時展開は最大3件。最後の利用者が中断すると取得も中断する。
上限値は `definition.ts` に定義する。これらは処理単位・キャッシュ単位の上限であり、ブラウザ全体のメモリ上限ではない。

開発時は共通リクエスト規則と開発用プロキシを使用し、本番では元のURLへ接続する。配信元のCORS設定が必要。

検証用データは `__fixtures__/test-store.ts` が生成する架空の格子だけを使用する。

## 地域索引付きGPMプロファイル

ルートの `attributes.gpm` に version 3 の地域索引があり、配列が `[tile, height, latitude, longitude]` の構造を持つ場合は専用アダプターで読む。
`tiles[].bounds` で地域ごとに配置し、高度方向の最大値を単一バンドの2Dラスターとして表示する。欠損値を透明にし、観測値0は保持する。地域間の空白は補間しない。
`detail` 選択時はズーム5未満で `overview` を使い、必要な地域のチャンクだけ取得する。`overview` 選択時は常に概観配列を使う。値の色付けと表示範囲は既存のラスター設定を使用する。集約または高度で切り出した地域格子は、追加の64 MiB上限の共有キャッシュで保持する。
これは特定の地域索引構造への対応であり、任意のGPM製品・任意の4次元Zarrの自動解釈を保証しない。立体表示は下記のボクセル描画に対応する。

各地域の `bounds.minHeight` / `maxHeight` がある場合、レイヤーの「高度」で最大値表示と指定高度の水平断面を切り替えられる。高度はmで指定し、上端を含まない高度区間の値を表示する。低ズームのoverviewでも指定した高度を含む層を選ぶ。高度軸の範囲・間隔は `properties.vertical`、選択状態は `state.vertical` に保持し、source URLに反映する。このプロファイルの日時情報は取得期間のメタデータであり、切り替えられる時間軸ではない。


## ボクセル表示

地域索引付きGPMプロファイルに高度範囲がある場合、登録方法を「2D表示／ボクセル表示」から選べる。
`RasterTiffStyle.volume` に表示方法、値の下限、高さ倍率を持ち、entryからボクセル描画仕様を生成する。
2D用のsource/layerは作らず、専用runtimeがMapLibreのcustom layerで描画する。Workerで地域チャンクを展開し、正のセルの位置・大きさ・値だけを転送する。0と欠損は描かない。

値の色と数値範囲、透明度は既存のラスター設定を使う。高さ倍率の初期値1は実際の高度で、地形面への吸着はしない。
画面内の地域を読み、縮小表示ではoverview、ズーム5以上では中心に近い最大4地域をdetail、それ以外はoverviewで描く（overview配列がある場合）。同時取得は2地域、1地域の正のセル数は125,000まで。保持するセル列・インスタンス行列・色の合計は64 MiBまでとし、上限超過はエラーとして通知する。制限値は `definition.ts` に置く。
メルカトル・球面表示の切り替えに対応する。透明度は通常の深度テスト付き描画であり、半透明ボクセルが重なる場合の厳密な奥行き順序合成は行わない。
