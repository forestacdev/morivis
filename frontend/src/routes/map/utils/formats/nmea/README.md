# NMEA 0183

GNSSの保存ログを`nmea-simple`（MIT）で解析し、WGS84の軌跡・計測点を通常のベクターentryへ変換する。通信規格全体やシリアル接続・AISを実装するものではない。

- `.nmea` / `.nme`、内容で識別できる `.txt` / `.log`。ZIP展開後も同じ判定を使用。複数ログはフォームで切り替え、1ファイルずつ登録する。
- チェックサム付きRMC / GGA / GLLから位置を取得。GP / GNなどのトーカーIDに対応。空行は無視し、非位置文は件数のみ表示する。各行はNMEA文から始まる必要があり、時刻などの独自プレフィックスは未対応。
- チェックサム欠落・不正、無効測位、範囲外の度分・方位・UTCは除外。位置文のエラー、逆順の時刻、5分超の空白、日付変更線で軌跡を分割する。孤立点は計測点で表示できる。
- 同時刻・同座標の連続する位置文は1点にまとめ、属性を補完する。座標が異なる文は統合しない。
- RMCの日付またはZDAで日付を確定する。それ以前の時刻だけの記録に日付を補わない。日付なしのGGA/GLLでライブラリが返す実行日は使わない。RMCの2桁年はライブラリと同じ73を境に1973–2072年へ対応させる。
- UTC時刻、平均海面からの高度、ジオイド高、衛星数、HDOP、測位種別、対地速度（m/s）、真北基準の針路を属性に保存。座標は2Dで、高度を地図の標高に使用しない。欠測数値は0で補完しない。
- 測地系指定がなければWGS84として扱う。DTMでWGS84以外を指定するログはエラーとし、オフセット変換は行わない。
- 入力32 MiB、出力25万点、Workerタイムアウト120秒。上限超過時は途中結果を登録しない。

文のデコードとチェックサム検証は既存ライブラリを利用する。morivis側では入力検証、整数の度分表記の正規化、ミリ秒を含む時刻の正規化、日付の継続、GeoJSON化を担当する。

参照: [nmea-simple](https://github.com/101100/nmea-simple)、[Trimble NMEA messages](https://receiverhelp.trimble.com/oem-gnss/nmea0183-messages-overview.html)
