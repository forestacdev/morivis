# Minecraft Java Edition MCA

地形リージョンの `.mca` をブラウザ内のWorkerで読み、頂点色付きGLBに変換する。
生成したファイルは既存の `MeshModelForm` → `MeshEntry` → three.js のフローに渡す。
読み込みフォームではファイルとチャンク範囲を選び、その後にMinecraft専用のジオリファレンスメニューを開く。
地図上のプレビューを見ながら、ワールド原点（X=0、Z=0）の緯度・経度と1ブロックの長さを指定して決定する。
ファイル名 `r.x.z.mca` からリージョン位置を読み、原点からのワールド座標を保って配置する。

## 対応範囲

- Java版1.13以降のブロックパレット形式（`Level.Sections` / `sections`）
- gzip・zlib・非圧縮のチャンク
- 1.13〜1.15の連続ビット列と1.16以降のlong境界パディング
- 負のチャンク座標・負のセクション高さ
- 同じワールド・ディメンションの地形MCAを複数ドロップ・複数選択可能。リージョン内のX/Zチャンク範囲（0〜31、両端を含む）を全ファイル共通で指定可能

1.12以前の数値ブロックID、LZ4圧縮、外部 `.mcc` はエラーで案内する。
`entities` / `poi` 内の同じ拡張子のファイルは地形として扱わない。
対応する保存構造を架空fixtureで検証しており、すべてのMinecraftリリースの実ワールドでの動作を保証するものではない。

## 読み込みダイアログのグリッド

ファイル名のX/Zから、地形の変換前にリージョン配置を表示する。選択済みの区画をハイライトする。
追加ドロップ・ファイル選択は既存の一覧に追加し、同じリージョンは新しいファイルで置き換える。
不正名の追加は通知して、既存の一覧を保持する。初回入力の不正ファイルは一覧から削除して修復できる。
グリッドは9列×7行の表示範囲を移動する方式で、離れたリージョンを含めても巨大なセル配列を作らない。
表示範囲外の区画数を示し、ファイル一覧からそのリージョンへ移動できる。
方向ボタンは周辺セルを含むグリッドを約240msでスクロールさせる。選択区画と原点マーカーも一緒に移動する。
連打は現在位置から新しい移動先へ追従し、動きを減らす端末設定では即時移動する。

## 複数リージョンの読み込み

複数のMCAは1つのGLB・レイヤーにまとめ、原点と縮尺を一度設定して一括配置する。
ファイルを1つずつWorkerで展開し、ファイル名と件数を進捗に表示する。ZIP内のMCA一式も同じ入口へ渡す。
ファイル名が不正、または同じリージョン座標が重複している場合は変換を開始しない。
途中のファイルにエラーがある場合はファイル名を表示し、セット全体を中止する。成功した一部だけを登録しない。
キャンセル・入力差し替え・フォーム破棄でWorkerを終了する。
各リージョンは別nodeのtranslationで位置を維持し、`format.minecraftRegions` に一覧を保存する。
`format.minecraftRegion` は先頭を保持し、従来の単体モデルとの互換性を保つ。
リージョン間の境界面は除去しない。

## モデル・テクスチャの事前配置

`PUBLIC_MINECRAFT_RESOURCE_URL` の素材をWorkerから自動取得する。利用者は `.mca` だけを選ぶ。
環境変数が空なら `frontend/static/minecraft/` を使用する。素材はGit管理対象外。
空の `manifest.json` では従来の色付きメッシュを生成する。
配置コマンドとCloudFront設定は [素材配置の説明](../../../../../../../docs/minecraft-resources.md) を参照。

- `blockstates` の `variants` / `multipart`、状態条件（OR / AND）、重み付き候補
- モデルの親継承、テクスチャの `#` 参照、要素の寸法・単軸／Euler回転・rescale
- ブロックのX/Y回転、面のUV・UV回転・uvlock
- PNGのアルファによる不透明・切り抜き・半透明の材質分離
- 使用画像をGLBへ埋め込み、複数リージョン間で画像を共通化

モデル未定義のブロックは立方体／ハーフブロックに戻す。親モデルや画像の欠損はファイル名を含むエラーにする。
`builtin/entity` などゲーム本体の専用描画が必要なモデル、液体は従来の色付き形状に戻す。
アニメーション画像は `.png.mcmeta` の先頭指定フレームを固定表示する。非アニメーションの長方形画像は切り詰めない。
`tintindex` はブロック名の代表色で近似し、バイオーム色・ゲーム内照明・AO・エンティティは再現しない。
重み付き候補は位置から安定して選択するが、Minecraftと同じ乱数列にはしていない。
半透明面は通常の深度ソートで描画するため、複雑に重なる透明面には表示順の限界がある。

素材ありの経路ではモデルの各面をそのまま生成し、隣接する不透明面や同種ガラスで完全に隠れる境界面を除く。
部分的にしか隠れない面は残す。従来の色付きメッシュの矩形結合は行わないため、面数・メモリ使用量は増える。
モデルと画像は変換処理内でキャッシュし、Worker終了時に解放する。
描画に使う材質の透過設定はGLBのextrasで識別し、既存の地図スタイル適用でも保持する。

## 素材未配置時の表示

Minecraft標準のハーフブロックは `Properties.type` の `bottom` / `top` / `double` に応じて、下半分・上半分・2枚重ねの形状を再現する。
空気は描画せず、その他のブロックは不透明の立方体として近似する。色はブロック名に基づく代表色で、未知の名前にも固定色を割り当てる。
テクスチャ、バイオームの色、照明値、ブロックの向き・階段などの形状、水やガラスの透過、エンティティは再現しない。

隣接セクション・チャンクを含めて内部面を除外し、同一ブロックの面を矩形にまとめる。
ハーフブロックがあるリージョンはY方向だけ0.5ブロック単位で占有判定し、部分的に接する面や上下の隙間を保持する。元のブロック配列は複製しない。
上下の形状はパレットIDで区別する。水没状態による水の追加描画は行わない。
形状の参照: [Fabric SlabType](https://maven.fabricmc.net/docs/yarn-24w18a%2Bbuild.2/net/minecraft/block/enums/SlabType.html)。
選択範囲の境界には断面を作る。GLBの座標単位は1ブロック。
元データの単位を `MeshEntry.format.sourceUnit: 'minecraft-block'` として保持し、初期値は1ブロック＝1mとする。
配置画面とレイヤー設定では、固定倍率を含めた実寸を「1ブロック＝○m」で指定できる。ドラッグによる拡大縮小もこの値に反映する。
画面サイズに合わせる初期倍率はMinecraftには適用しない。通常のGLBなどは従来どおりの倍率操作を使う。
ブロック編集・ワールドの書き戻しには対応しない。

## ワールド原点

リージョンのX/Zは512ブロック単位で、X正方向を東、Z正方向を南、Y正方向を上として配置する。
名前とNBTのチャンク座標が一致することを検証し、異なる場合は元のファイル名を確認するよう案内する。
GLBの頂点はメッシュ近傍の座標のまま保持し、nodeのtranslationでワールド座標へ戻す。
一部のチャンクだけを選んだ場合も、空の範囲や負の座標を詰めずに元の位置を保つ。Y=0の基準も保持する。

`MeshEntry.format.minecraftRegion` を持つモデルでは中心・接地への正規化を行わず、
`style.transform.lng/lat` をワールド原点として扱う。配置は既存のMercatorモデル行列を使い、
同一原点・同一縮尺のリージョン境界を一致させる。メートル換算は指定原点の緯度を基準とする。
縮尺変更はワールド原点を中心に行うため、リージョンまでの距離も同じ倍率で変わる。
レイヤー設定から原点を変更できる。複数レイヤーを合わせる場合は同じ原点と縮尺を指定する。

専用メニューには現在の地図中心を原点にするボタンと地形を表示するボタンがある。
直前にジオリファレンスを確定した原点と縮尺を同じセッションの次回入力に引き継ぐ。キャンセルした設定は保存しない。
地図上のボックスのドラッグで原点を移動できる。縮尺は原点を中心に変えるため、汎用モデルの対角点固定の回転・拡大縮小ハンドルは表示しない。
MCAからの変換ファイルには確定済み配置を付けず、前回の設定があっても必ず専用メニューで確認する。

## リージョングリッド

読み込んだ各リージョンとそれぞれの周囲8区画を、512×512ブロックのポリゴンと `r.x.z.mca` ラベルで表示する。
読み込み対象の区画は塗りを濃くする。位置合わせ中のガイドとして表示し、完了時にはグリッド・ラベルを非表示にする。
位置合わせを開き直すとガイドを再表示する。通常表示でも必要な場合はレイヤー設定から明示的に有効にできる。
位置合わせ中もグリッド・ラベルを個別に切り替えられる。
地形と同じ変換行列から境界を生成し、原点・縮尺・回転に追従する。チャンクの部分読み込みでも区画は縮めない。
同一原点・縮尺・回転で複数リージョンを表示するときは重なる区画を統合する。

`MeshStyle.minecraftGrid` に通常表示の設定を保持し（未設定は非表示）、描画時にポリゴンの `MorivisLayerEntry` へ派生させる。
通常の `createSourcesItems` / `createLayersItems` → `mapStore.setStyle` 経由で更新し、地形より上にガイドを重ねる。
位置合わせ中は有効なdraftのグリッドを表示し、無効入力中は直前の有効値を維持する。キャンセルで元の配置へ戻す。
地形の非表示・削除とMap破棄時には派生データを解放する。

## ファイルと上限

- `nbt.ts`: big-endian NBT、長さ・深さ・ノード数を検証
- `region.ts`: MCAヘッダー検証、チャンク展開、共通パレットへの正規化
- `batch.ts` / `batch-convert.ts`: ファイルセット検証・逐次変換・累積上限
- `mesh.ts`: 内部面除去・面結合
- `glb.ts`: Workerで動くGLB 2.0書き出し
- `world-placement.ts` / `model-file.ts`: ファイル名・原点設定の検証とモデル配置情報への引き継ぎ
- `analyze.ts` / `worker.ts`: 進捗通知とWorker終了によるキャンセル

入力256 MiB/ファイル、展開後NBT32 MiB/チャンク、32,768の非空セクション/ファイルが上限。
面数制限の選択欄は設けず、既定で面数による停止を無効にする（`maxFaces: 0`相当）。
読み込める量は端末のメモリとGLB形式の4 GiB未満という制約に依存する。
リージョンごとのメッシュは使用部分だけの配列にして、未使用の確保領域を累積させない。
MCAのみの入力では合計100 MiBの汎用確認を省略する。

仕様確認に利用した実装: [PrismarineJS Anvil provider](https://github.com/PrismarineJS/prismarine-provider-anvil)、[リージョン名・チャンク位置の実装](https://github.com/PrismarineJS/prismarine-provider-anvil/blob/master/src/anvil.js)。
Node用ファイルI/Oには依存せず、NBT・region読み取りとメッシュ生成は独立した関数としてテストする。
