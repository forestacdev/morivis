# データパイプライン

morivis は、ファイルや URL から受け取ったデータを解析し、座標系や配置を確定してから地図へ登録する。
この文書では、データ変換の全体像と処理の役割分担をまとめる。

## 全体像

```mermaid
flowchart LR
    A["ファイル・URL"] --> B["形式の判定"]
    B --> C["データの解析・変換"]
    C --> D{"座標系・配置が分かるか"}
    D -- はい --> G["レイヤーの作成"]
    D -- 座標系が不明 --> E["座標系を選択して変換"]
    D -- 位置が不明 --> F["地図上で位置合わせ"]
    E --> G
    F --> G
    G --> H["プレビュー・登録"]
    H --> I["地図に描画"]
```

## 入力と解析

入力ファイルは、拡張子・内容・関連ファイルの組み合わせから形式を判定し、対応するフォームとパーサーへ渡す。
URL の場合は、配信元のメタデータを読み、データの種類や取得方法を確認する。

形式ごとのパーサーは、図形と属性、画像や格子、点群、モデルなど、後続の処理で扱えるデータへ変換する。
重い解析・座標変換・メッシュ生成は主に Worker で処理し、画面側は入力の選択や進行状態を扱う。

## 主な変換

| 入力の種類 | 主な変換先 |
| --- | --- |
| ベクター・表・ログ | 図形と属性をまとめた地物データ。表の座標列やログの位置情報からも点・線を作る。 |
| 画像・格子 | 地図上に配置する画像や数値バンド。標高格子は3Dメッシュにも変換できる。 |
| 点群・サーフェス | 点群やメッシュとして扱うほか、標高格子へ変換してラスター表示できる。 |
| 3Dモデル | 必要に応じて描画可能なモデル形式へ変換し、単位・向き・配置を設定する。 |
| タイル・リモート配信 | 配信先と表示設定をレイヤーに持たせ、描画時に必要な範囲を取得する。 |

同じ入力でも、用途に応じてベクター・ラスター・3Dモデルなどの表示方法を選べる場合がある。
変換結果は共通の内部モデル `MorivisLayerEntry` にまとめ、UIとストアで扱う。

## 座標系と位置合わせ

埋め込み情報や付属ファイルから座標系を取得できる場合は、それを使って地図上の位置を求める。
ベクターは基本的にWGS84の経緯度へ変換し、ラスターやモデルは描画に必要な座標変換・配置情報を準備する。

座標系が不明な場合は、座標系選択（Zone）で投影法を確定してから変換する。
位置情報がない画像や図面などは、位置合わせ（GeoRef）で地図上の四隅を指定する。座標系の選択後に位置合わせへ進む場合もある。
3Dモデルでは、地図上の位置・向き・大きさを調整する。

ベクターや点群の位置合わせには一時的なプレビュー画像を使うが、確定時には元の図形や点群へ変換を適用する。

## レイヤーの作成と登録

通常は各フォームがレイヤーを作り、位置合わせを経たデータは共通の確定処理でレイヤーを作る。
登録前に地図上でプレビューし、確定したレイヤーを一覧へ追加する。複数のレイヤーをまとめて登録する場合もある。

登録後は、レイヤーの定義から描画用の設定を生成し、MapLibre・deck.gl・three.jsへ渡す。
プレビューや処理中の一時状態は、保存・同期するレイヤーの定義と分けて扱う。

## 実装の役割分担

以下のパスは `frontend/src/routes/map/` を基準とする。

| 処理 | 主な実装 |
| --- | --- |
| 入力の受付・形式判定 | `components/upload/` の `FileManager.svelte`、`upload-drop.ts`、`upload-drop-matchers.ts` |
| フォームの選択 | `components/upload/dialog-registry.ts` |
| 形式ごとの解析・変換 | `utils/formats/`、`components/upload/form/` |
| 座標変換・位置合わせ | `utils/proj/`、`utils/transform/`、`components/upload/transform-policy.ts` |
| 位置合わせ後のレイヤー作成 | `components/upload/form/transform/finalize-georef.ts`。`+page.svelte` は生成結果のプレビュー登録・通知・画面の終了を扱う |

形式ごとの対応範囲や制限は、`utils/formats/<format>/` の実装・定義・READMEを参照する。
内部モデルと描画系の境界は [内部レイヤーモデル](./architecture/entry-model.md)、検証方法は [開発・検証](./development.md) を参照する。

### 動的フォームのprops

`components/upload/dialog-props.ts` がフォーム分類ごとの入力を定義し、`dialog-registry.ts` の `defineDialog()` が登録するフォームのpropsと照合する。ロード結果は分類とコンポーネントの組を保持し、`DialogRenderer.svelte` は分類を絞り込んで対応するpropsを渡す。フォームを追加するときは、既存の分類で必要な値を渡せるか確認する。
